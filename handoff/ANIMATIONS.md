## 1. Загальні правила

### 1.1. Чотири типи анімацій

| Тип | Як працює | Де |
|---|---|---|
| **A. Від часу, один раз при завантаженні** | CSS `animation … backwards` | поява hero |
| **B. Від часу, по колу** | CSS `animation … infinite` | стрічки, єнот, кільця з текстом, моргання очей |
| **C. Від скролу (scrub)** | JS щокадру рахує прогрес 0…1 з позиції елемента і пише його в стиль. Скрол назад програє анімацію задом наперед | маніфест, абзаци теми, «100%», назви зон, маршрут, паралакс |
| **D. Від події** | клас на елементі + CSS `transition` або `animation` | наведення, клік, поява у вікні, меню |

Типи умовні: до C віднесено й те, що скрипт рахує щокадру від миші (зіниці, нахил квитка, паралакс контурів), а перемикання літер hero (5.2) — це таймер у скрипті, не CSS.

### 1.2. Криві (easing), які повторюються

| Назва в цьому документі | Значення | Характер |
|---|---|---|
| `back-s` | `cubic-bezier(.3,1.8,.5,1)` | різка «пружина» з перельотом — кнопки |
| `back-m` | `cubic-bezier(.3,1.6,.5,1)` | м'якша пружина — фото, квиток |
| `back-l` | `cubic-bezier(.2,1.25,.3,1)` | легкий переліт — поява hero |
| `out` | `cubic-bezier(.2,.8,.2,1)` | плавне гальмування без перельоту |

### 1.3. Брейкпойнти, що впливають на анімації

- `max-width: 820px` — телефон/планшет: меню-бургер, свайп замість стрічок, складений абзац теми, інші параметри квитка і єнота.
- `max-width: 520px` — повільніші лапи єнота.
- `hover: none` — немає фото, що вилітають у зонах.
- `hover: hover` — сильніше збільшення фото галереї (`1.09` з тінню) лише там, де є миша; базове `.ph:hover { scale: 1.04 }` медіазапитом не обмежене.
- Скрипт для паралаксу вважає телефоном ширину **менше** 820 px (`vw < 820`), а стилі й маршрут — **до 820 px включно**. Тому рівно на 820 px розкладка телефонна, а паралакс повної сили. Так в еталоні; зберегти як є.

### 1.4. Зменшений рух (`prefers-reduced-motion: reduce`)

Правило: у цьому режимі нічого не рухається само, але **все лишається видимим і досяжним**.

- CSS: `.vw *, .vw *::before, .vw *::after { animation: none !important; transition: none !important }`.
- JS: функції `layout()` (усе від скролу) та `eyes()` (зіниці) **не викликаються**; не запускається випадкове перемикання літер hero, не створюються спостерігачі появи. Таймер і кліки працюють.

Що зроблено, щоб без руху нічого не загубилось (перші чотири рядки — правила в блоці `@media (prefers-reduced-motion: reduce)`, останні два — поведінка скрипта):

| Що | Правило | Навіщо |
|---|---|---|
| локація: підписи, точки, пін | `.place-sp { scale: 1; rotate: var(--r) }`, `.place-rt .dot, .place-pin { scale: 1 }` | у спокої вони мають `scale: 0`, а вмикає їх `layout()`, який тут не працює. Лінія маршруту намальована за замовчуванням (`stroke-dashoffset: 0`) |
| стрічки фото й відгуків | `.strip, .revs { overflow-x: auto; overflow-y: hidden; scrollbar-width: none; cursor: grab }`, друга доріжка `.mq-t[aria-hidden]` — `display: none`; ще три дрібні правила там само: смуга прокрутки схована (`::-webkit-scrollbar { display: none }`), `.strip.drag, .revs.drag { cursor: grabbing }`, `.strip .ph img { -webkit-user-drag: none }` | стрічки стоять, тому їх можна прокрутити вручну: трекпадом, колесом із Shift або перетягнути мишею (той самий код, що в 10.2). Без цього при 1280 px не видно фото 5–9 і відгуків 5–8 |
| єнот | `.coon { left: 78%; bottom: 22% }` | не бігає, а стоїть на скосі в межах екрана. Без цього він лишається за лівим краєм |
| перехід за якорем | `html { scroll-behavior: auto }` | стрибок до секції миттєвий; у звичайному режимі — плавний |
| банер cookies | окремого правила немає: без анімації появи картка одразу стоїть на місці; після відповіді скрипт ховає її без затримки | 3.5 |
| доводка стрічки після перетягування | у скрипті `behavior: reduce ? 'auto' : 'smooth'` | теж без руху |

Що в цьому режимі лишається як є, свідомо:

- стіна тексту у футері стоїть; це прикраса (`aria-hidden`), яка повторює дату й адресу, що є на сторінці;
- назви зон мають запасну ширину `"wdth" 330` (скрипт `--wd` не пише);
- літери назви в hero перемикаються при наведенні — це миттєва зміна від дії людини, а не анімація.

**Це обов'язково зберегти.** Перевіряється автоматично (`checks/behaviour.js`): з увімкненим `prefers-reduced-motion` жоден елемент не має `opacity: 0`, `scale: 0` чи `visibility: hidden`, стрічки прокручуються до останньої картки, єнот у межах екрана. Сховані навмисно і в перевірці пропускаються: фото, що вилітають у зонах (`.z-ph`), другий напис кнопки копіювання (`.cp-b`) і її галочка, згорнуте пояснення теми на телефоні (`.pov-x`), закрите меню (`.mnav`), а також усе всередині стіни тексту (`.wall`) і других доріжок стрічок (`.mq-t[aria-hidden]`).

### 1.5. Один цикл `requestAnimationFrame`

Весь JS-рух живе в одній функції `frame(ts)`:

1. рахує ключ `top кореня | innerHeight | innerWidth | mouseX | mouseY | висота кореня`;
2. якщо ключ змінився — викликає `layout(vh, vw)` (усе від скролу і від миші);
3. щокадру викликає `eyes(ts, vh, vw)` (зіниці).

Тобто `layout` не працює, коли нічого не рухається. При перенесенні цю оптимізацію зберегти.

### 1.6. Змінні миші

`pointermove` зберігає `m.x, m.y, m.t` і `m.mouse` — чи це справжня миша (`e.pointerType === 'mouse'`). До першої події: точка (`innerWidth / 2`, `innerHeight / 3`), `m.mouse = false`. `layout` пише на кореневий елемент:

- `--mx = (m.x / vw) * 2 − 1` — від −1 (лівий край) до 1 (правий);
- `--my = (m.y / vh) * 2 − 1` — від −1 (верх) до 1 (низ).

### 1.7. Формула прогресу скролу (атрибут `data-prog`)

Для елемента з `data-prog="K"` і необов'язковим `data-ps="S"` (типово 0.92):

```
p = clamp( (vh * S − rect.top) / (vh * 0.62 + rect.height * 0.5) * K , 0, 1 )
```

- `S` — на якій частці висоти екрана має бути верх елемента, щоб анімація **почалась** (0.86 = верх елемента на 86% висоти екрана, тобто елемент уже помітно в кадрі).
- `K` — множник швидкості: більше `K` — анімація закінчується раніше.
- `p` пишеться в CSS-змінну `--p` елемента.

### 1.8. Що скрипт шукає в розмітці

Повний перелік. Якщо при перенесенні щось із цього зникне з розмітки — відповідна анімація здебільшого мовчки перестане працювати, помилки не буде. **Один виняток — таймер:** якщо лишити `data-cd="d"`, але прибрати котрийсь із трьох інших, скрипт упаде на старті, і не запрацює вже нічого (ні поява блоків, ні кліки, ні рух від скролу).

Коли скрипт шукає елементи: більшість — один раз при старті (hero, паралакс, `data-prog`, назви зон, очі, квиток, маршрут, таймер, літери, цифри, блоки `.rv`); слова маніфесту й абзаців, лінії та зупинки маршруту — при першому перерахунку; усе, що реагує на клік чи клавішу (меню, зміна точки зору, копіювання, банер cookies, слово «тему», стрічки), — у момент події. Тому розмітка має бути на місці до старту скрипта.

| Гачок у розмітці | Скільки | Що робить скрипт | Розділ |
|---|---:|---|---|
| `data-vw` | 1 | корінь сторінки: на нього ставляться класи `flip`, `menu`, `tmore`, на мить `swap`, і змінні `--mx`, `--my` | 1.6, 3.4, 4 |
| `data-hero` | 1 | пише `--hs` | 5.3 |
| клас `L` з `data-d`, `data-k`, `data-g` | 11 літер | перемикає клас `it`, пише `--k` | 5.2 |
| `data-par` | 4 | паралакс: пише `translate` | 6 |
| `data-prog` (з `data-ps`) | 5 | пише `--p` | 1.7 |
| `data-words` і слова `.w` з `data-dx`, `data-r` | 4 блоки | пише `transform` кожному слову | 6, 7 |
| клас `z-t` з `data-max` | 6 | пише `--wd` | 8 |
| `data-sock` | 4 | рухає перший дочірній елемент (зіницю): два ока в заголовку «Точка зору» і два в банері cookies | 7, 3.5 |
| `data-ck="yes"`, `data-ck="no"` | 2 | кнопки банера cookies: ставить на картку `.cbn` клас `yes` або `no`, ховає її і повідомляє відповідь подією `vw-cookies` | 3.5 |
| клас `stat` | 3 | ставить `pre` / `go` на `.stat-n>span` | 9 |

| `data-tilt` | 1 | пише `transform` (лише під мишею) | 12 |
| `data-cd="d"`, `"h"`, `"m"`, `"s"` | 4 | таймер: пише текст | 5.6 |
| `data-act="menu"` | 1 | відкриває й закриває меню | 4 |
| `data-act="flip"` | 3 | змінює точку зору | 3.4 |

Ще чотири місця, де скрипт спирається на розмітку: клас `nav-bg` (бургеру пишеться `aria-expanded`); `.mnav a` і `.nav-logo` (клік закриває меню); `.mq-t:not([aria-hidden]) > *` (картки, між якими стрибає перетягування); `id="pov-x"` (пишеться в `aria-controls` слова «тему»).

У розмітці є ще `data-act="more"` на слові «тему» — скрипт його не читає (шукає за класом `tm`).

Події, які слухає скрипт: `pointermove` (позиція миші; перетягування), `pointerdown`, `pointerup`, `pointercancel` (перетягування стрічок мишею), `pointerover` (літери hero), `click` (меню, зміна точки зору, копіювання, слово «тему», відповідь у банері cookies), `keydown` (`Escape` закриває меню; `Enter` і пробіл на слові «тему»), `resize` (ширше 820 px меню закривається; слово «тему» перестає бути кнопкою). Слухача `scroll` немає — позицію скролу читає цикл з 1.5. Плавний перехід за якорями (пункти навбара й меню, лого, кнопка відео) робить не скрипт, а стилі: `html { scroll-behavior: smooth }` і `.sec { scroll-margin-top: 56px }`. Скрипт стартує одразу, а якщо сторінка ще завантажується — після `DOMContentLoaded`.

Таймери: `setInterval` 1000 мс (таймер зворотного відліку), `setInterval` 1700 мс (літери hero), `setTimeout` 2200 мс (напис «Адресу скопійовано»), `setTimeout` 520 мс (кінець перетягування стрічки), `setTimeout` 650 мс (банер cookies прибирається після відповіді). Два `IntersectionObserver`: поява блоків (3.3) і цифри (9).

## 3. Глобальні елементи

### 3.1. Кнопки `.btn`

Базовий стан: `rotate: -2deg`, об'ємна тінь (шар внутрішніх і зовнішніх `box-shadow`).

| Стан | Зміни |
|---|---|
| `:hover` | `rotate: 1.5deg`, `scale: 1.05`, зовнішня тінь довша (до `0 44px 24px`) |
| `:active` | `translate: 0 4px`, `scale: 1`, зовнішня тінь майже зникає — кнопка «втиснута». У малої `.btn-s` тінь при натисканні лишається як при наведенні (правило `.btn-s:hover` стоїть пізніше); зсув і масштаб діють |

Переходи: `rotate .3s back-s`, `scale .3s back-s`, `translate .16s ease`, `box-shadow .2s ease`.

Варіанти: `.btn-s` (мала, в навбарі) — на hover коротша тінь; сіра `.btn.cp` (їх дві: «Скопіювати адресу» і «Змінити точку зору» в меню) — на hover нахиляється, збільшується і отримує довшу тінь, як усі кнопки, але **не міняє колір**: правило `.btn.cp:hover { color: var(--fg) }` для цього й стоїть.

Використовуються окремі властивості `rotate` / `scale` / `translate`, а не `transform`. Це навмисно: вони не конфліктують між собою і з анімацією появи.

### 3.2. Текстові посилання `.lnk`

На hover: `font-variation-settings: "wght" 900, "wdth" 940` + `font-style: italic`. Перехід `font-variation-settings .3s`. Базово `"wght" 820, "wdth" 700`.

### 3.3. Поява блоків `.rv` (23 елементи)

- Початковий стан `.rv.pre`: `opacity: 0; translate: 0 56px`.
- Перехід: `opacity .7s ease, translate .8s cubic-bezier(.2,.9,.2,1)`.
- Логіка (JS, `IntersectionObserver`, `rootMargin: 0px 0px -4% 0px`, `threshold: 0.02`):
  - при завантаженні клас `pre` отримують **лише ті** `.rv`, чий верх нижче 92% висоти екрана. Те, що вже на екрані, не ховається;
  - коли елемент входить у вікно — `pre` знімається, спостереження за ним припиняється. **Один раз, назад не програється.**

### 3.4. Зміна точки зору

Кнопки з `data-act="flip"` (око в навбарі, велика кнопка в темі, кнопка в мобільному меню) перемикають клас `flip` на кореневому елементі `.vw`.

- CSS: `.g, .vw.flip .p { …сірий фон, рожевий текст… }`, `.p, .vw.flip .g { …навпаки… }`, `.vw.flip { background: var(--pink) }`.
- **Перехід миттєвий, без анімації кольору.** Це навмисно. Рядки зон мають `transition: background .22s, color .22s` для наведення; щоб вони не перефарбовувались плавно під час зміни точки зору, скрипт на мить ставить на корінь клас `swap` (`.vw.swap .z { transition: none }`): `classList.add('swap')` → `classList.toggle('flip')` → примусовий перерахунок стилів (`void root.offsetWidth`) → `classList.remove('swap')`. Усе в одному обробнику кліку, без таймерів.
- Правило `.vw.flip { background }` обов'язкове: фон кореня видно в трикутнику під нижнім скосом секції квитків, і без цього правила він лишився б не того кольору.

### 3.5. Банер згоди на cookies

Картка `.cbn` (вигляд і розміри — `SPEC.md`, розділ 16). Вона лежить поверх сторінки (`position: fixed`), під навбаром і під мобільним меню. Рух:

### 5.2. Літери назви перемикаються прямі ↔ курсив

11 літер `.L`. Клас `it` = курсив. Перемикання **миттєве**, без переходу.

- **Саме по собі:** кожні 1700 мс одна випадкова літера змінює стан. Лише коли hero ще на екрані (`rect.bottom >= 0`) і рух не вимкнено.
- **Від миші:** `pointerover` на літері перемикає її, якщо миша зрушила щонайменше на 12 px від місця попереднього перемикання (`dx² + dy² >= 144`) і цю літеру не перемикали мишею останні 600 мс (перемикання за таймером цей лічильник не зачіпає). Обмеження потрібні: перемикання змінює ширину літери, сусіди зсуваються під курсор, і без них літери мерехтять.
- **Кернінг:** після перемикання перераховується `--k` для цієї літери й наступної (`kernL`). Якщо пара в «логотипному» стані (класи збігаються з `data-d` обох літер) — береться `data-k`; інакше `data-g` або таблиця `[[-0.085, -0.118], [-0.122, -0.095]]` за індексами `[попередня курсивна][ця курсивна]`.

### 5.3. Назва стискається при скролі (тип C)

```
--hs = clamp( −hero.top / (hero.height × 0.8), 0, 1 )
```

- `.ln { font-variation-settings: "wght" 400, "wdth" calc(835 − var(--hs) × 560) }` — ширина літер 835 → 275;
- `.L { margin-left: calc(var(--k, 0) × (1 − var(--hs) × .72) × 1em) }` — кернінг слабшає разом із шириною.

### 5.4. Контури зіниці `.hero-eye`

- Паралакс від скролу: `data-par="0.1"` (формула в 6.2).
- Паралакс від миші на групі `.hero-eye-g`: `translate: calc(var(--mx) × −14px) calc(var(--my) × −9px)`, перехід `translate .5s out`.

### 5.5. Кнопка відео `.play`

- Кільце з текстом `.play .ring`: `vw-spin` — `rotate(360deg)`, 14 с, `linear infinite`.
- hover: `rotate: 5deg; scale: 1.07`; active: `scale: .98`. Перехід `rotate/scale .3s back-s`. Базовий нахил `rotate: -7deg`.

### 5.6. Таймер

`setInterval(tick, 1000)`. Ціль — початок фестивалю: `Date.UTC(2026, 10, 22, 11, 0, 0)` = 22.11.2026 13:00 за Києвом (UTC+2). Пише числа в `[data-cd="d|h|m|s"]`: дні без нуля попереду, години, хвилини й секунди — двома цифрами; після дати зупиняється на нулях. Анімації цифр немає.

## 6. Про фестиваль

### 6.1. Маніфест `.mani` — слова вилітають зі скролом (тип C)

Атрибути: `data-prog="1.25" data-ps="0.82" data-words="1"`. Кожне слово — `<span class="w" data-r="…" data-dx="…">`.

Для слова номер `j` з `n` слів (константа `kk = 2.6`):

```
u = clamp( (p × (n + kk) − j) / kk, 0, 1 )      // прогрес цього слова
q = 1 − u
transform = translate(q × dx px, q × 0.5em) rotate(q × r deg) scale( clamp(u × 2.2, 0, 1) )
```

- При `u = 1` `transform` прибирається зовсім (порожній рядок).
- `data-r` — початковий нахил слова в градусах (близько ±5…10), `data-dx` — початковий зсув по горизонталі в px. Значення в кожного слова свої, вони в розмітці.
- Масштаб доходить до 1 на 45% шляху слова (`u × 2.2`), решта — вирівнювання нахилу. Слово спершу «виростає», потім «стає рівно».
- Слова йдуть із перекриттям: кожне наступне починає, коли попереднє пройшло ~38% свого шляху.
- Скрол назад програє все у зворотному порядку.

### 6.2. Фото `.ph-a`, `.ph-b`, `.ph-c`

- **Паралакс** (`data-par` = 0.1 / 0.05 / 0.14):

  ```
  ty = clamp( −(центр елемента − vh/2) × data-par × (vw < 820 ? 0.45 : 1), −260, 260 )
  style.translate = `0 ${ty}px`
  ```

  Центр рахується **без** уже застосованого зсуву (`rect.top − попередній ty`), інакше виникає зворотний зв'язок. Не рахується, коли елемент далі ніж 1.6 екрана знизу або 0.6 екрана зверху.

- **hover:** `scale: 1.04; rotate: 0deg; z-index: 5`, перехід `scale/rotate .35s back-m`. Базові нахили: 3.5° / −4° / 5°.

## 7. Тема фестивалю («Точка зору»)

### 7.1. Очі в заголовку — моргання

Дві «О» в заголовку — елементи `.sock.eyeO` із зіницею `.pupil` всередині.

`vw-blink`: `0%, 92%, 100% { scaleY(1) }  95% { scaleY(.08) }`, 5.5 с, `infinite`. Друге око — `animation-delay: .12s`.

### 7.2. Зіниці стежать за мишею (щокадру, `eyes()`)

Для кожного `[data-sock]` (їх чотири: два ока в заголовку і два в банері cookies), якщо він у межах екрана ±100 px:

```
ціль (tx, ty) = позиція миші
якщо миша не рухалась понад 2600 мс:
    tx = vw × (0.5 + 0.42 × sin(ts / 1700))
    ty = vh × 0.5 × (1 + 0.5 × sin(ts / 1100 + 1))        // очі «роздивляються» самі

(dx, dy) = ціль − центр ока;   d = довжина (dx, dy)
rxm = max(0, ширина/2 − рамка − радіус зіниці − 2) × 0.92   // і так само rym по висоті
k = min(1, d / 260)
pupil.transform = translate( dx/d × rxm × k,  dy/d × rym × k )
```

Зіниця не виходить за рамку ока; що ближче курсор, то менше вона відхилена. На телефоні очі «роздивляються» самі; після руху пальцем по екрану (прокрутка, свайп) вони 2.6 с дивляться в ту точку (`pointermove` слухається для будь-якого вказівника; простий дотик без руху такої події не дає), потім знову блукають. До першої події вказівник вважається в точці (`innerWidth / 2`, `innerHeight / 3`), давність — нескінченна.

### 7.3. Контури зіниці `.pov-bgl-g`

Паралакс від миші: `translate: calc(var(--mx) × −10px) calc(var(--my) × −7px)`, перехід `.5s out`. Стосується і верхньої частини, і «хвоста» під текстом.

### 7.4. Три абзаци вилітають зі скролом (тип C)

Той самий механізм, що в маніфесті, але одиниця — абзац. Кожен `<p>` має `data-prog="1.5" data-words="1"` і один `<span class="pp w" data-r="…">` усередині.

| Абзац | `data-ps` | `data-r` |
|---|---|---|
| великий («У культурі, мистецтві…») | 0.86 | −4 |
| «"Точка зору" змінює цю рамку…» | 0.80 | 3.4 |
| «У Львові продовжуємо тему…» | 0.74 | −3 |

На екрані 1280×720: перший абзац починає з'являтись, коли його верх на 86% висоти екрана, повного розміру досягає приблизно на 70%, вирівнюється близько 52%. Другий і третій починають на 6% висоти екрана пізніше кожен (80% і 74%); далі їхні пороги трохи розходяться, бо абзаци різної висоти.

Вимірюється прямокутник `<p>`, а трансформується вкладений `.pp`. **Не міряти те, що трансформується** — буде зворотний зв'язок.

### 7.5. Телефон: абзац за словом «тему»

До 820 px абзац «"Точка зору" змінює цю рамку…» (`.pov-x`) згорнутий. Слово «тему» в останньому абзаці (`.tm`) підкреслене і працює як кнопка.

- JS `syncTm()`: до 820 px ставить `role="button"`, `tabindex="0"`, `aria-controls="pov-x"`, `aria-expanded`; ширше — знімає їх.
- Клік / `Enter` / пробіл → клас `tmore` на корені.
- Згорнуто: `grid-template-rows: 0fr; visibility: hidden`, текст `opacity: 0`.
- Розгорнуто: `grid-template-rows: 1fr; visibility: visible`, текст `opacity: 1`.
- Переходи: `grid-template-rows .45s out`; `opacity` — `.35s` із затримкою `.12s` при відкритті, `.25s` при закритті; `visibility` перемикається одразу при відкритті і через `.45s` при закритті.
- `order: 3` — абзац розгортається **під** абзацом зі словом «тему», щоб текст не стрибав з-під пальця.
- `.pov-x .pp { transform: none !important }` — на телефоні цей абзац не бере участі в анімації від скролу (7.4), інакше після тапу він міг би лишитись зі `scale: 0`.

### 8.1. Назви зон розширюються біля середини екрана (тип C)

### 9.1. «100%» розтягується зі скролом (тип C)

### 9.2. Цифри 3 / 11 / 5.7 — пружина (тип D)

Елемент — `.stat-n > span`. Стани:

- `.pre`: `"wght" 1000, "wdth" 100` — вузько, очікування;
- `.go`: `animation: vw-wd 1.56s linear both`;
- фінал і стан без JS: `"wdth" 210`.

```css
@keyframes vw-wd {
  0%    { "wdth" 100; animation-timing-function: cubic-bezier(.3,0,.2,1) }
  36.7% { "wdth" 400 }
  60%   { "wdth" 150 }
  80%   { "wdth" 250 }
  100%  { "wdth" 210 }
}
```

(у кожному кадрі також `"wght" 1000`). Суть: різко розтягнулось далеко за норму, відскочило назад нижче норми, ще раз гойднулось і стало. **Саме відскок — те, що погоджено; простий плавний ріст не підходить.**

Затримки: друга цифра `.18s`, третя `.36s`.

Тригер — `IntersectionObserver` на картці `.stat`, `threshold: [0, 0.98]`:

- картка видима на ≥98% → зняти `pre`, додати `go`;
- картка **повністю** зникла з екрана → зняти `go`, додати `pre`;
- проміжні стани нічого не міняють.

Тобто анімація грає, коли цифра повністю в кадрі, і грає знову щоразу, коли до неї повертаються. Поки цифра хоч частково на екрані, вона не скидається.

## 10. Галерея і відгуки

### 10.1. Десктоп (ширше 820 px): стрічки, що їдуть самі; наведення на картку

Розмітка: `.mq` містить **дві однакові** доріжки `.mq-t` (друга з `aria-hidden="true"`).

```css
.mq-t { animation: vw-mq var(--dur) linear infinite }
@keyframes vw-mq { to { transform: translateX(-100%) } }
```

Кожна доріжка зсувається рівно на власну ширину — шов непомітний.

| Стрічка | `--dur` | Напрям |
|---|---|---|
| фото `.strip` | 82 с | справа наліво |
| відгуки `.revs` (`.mq-r`) | 84 с | зліва направо (`animation-direction: reverse`) |

Наведення:

- фото (лише `hover: hover`): `scale: 1.09; rotate: 0deg; z-index: 5; box-shadow: 0 18px 34px rgba(0,0,0,.3)`, перехід `scale/rotate .4s back-m, box-shadow .3s ease`;
- відгук: `rotate: 0deg; scale: 1.05; z-index: 4` — картка вирівнюється і збільшується; перехід `rotate/scale .35s cubic-bezier(.3,1.7,.5,1)`. Селектор саме `.revs .rev:hover`: він має бути вагомішим за правила нахилу карток (`.rev.ra`, `.rb`, `.rc`, `.rev:nth-child(n)`), які стоять у таблиці стилів пізніше.

**Стрічки при наведенні не зупиняються.**

Базові нахили: фото непарні −2.5°, парні 3° і на 34 px нижче; відгуки від −2.5° до 2.6°, у кожного свій.

### 10.2. Телефон (до 820 px): свайп по одній картці

Те саме перетягування мишею працює і на десктопі, коли ввімкнено `prefers-reduced-motion`: стрічки там стоять і прокручуються вручну (1.4). Прив'язки до карток (`scroll-snap`) і бічного відступу в тому режимі немає — доводить до картки лише скрипт після перетягування.

- Анімація стрічки вимкнена (`animation: none`), друга доріжка прихована.
- Контейнер: `overflow-x: auto; scroll-snap-type: x mandatory; scroll-padding: 0 var(--pad); overscroll-behavior-x: contain`, смуга прокрутки схована.
- Картки: `scroll-snap-align: start; scroll-snap-stop: always` — один жест = одна картка.
- Ширина: фото `70vw` (не більше 340 px), відгук `80vw` (не більше 380 px). Наступна картка визирає праворуч.
- Стрічка має початок і кінець (9 фото, 8 відгуків), по колу не йде.

Перетягування мишею (JS; потрібне у вузькому вікні на комп'ютері і в режимі зменшеного руху):

1. `pointerdown` мишею на `.strip` / `.revs`, якщо в контейнера `overflow-x: auto` → запам'ятати `x` і `scrollLeft`, додати клас `drag` (вимикає snap, інакше прокрутка смикається);
2. `pointermove` → `scrollLeft = початковий − (x − початковий x)`;
3. `pointerup` → знайти картку, з якої почали; якщо зсув більше 24 px — перейти на сусідню в бік руху, інакше повернутись; `scrollTo({ behavior: reduce ? 'auto' : 'smooth' })`; через 520 мс зняти `drag` (snap вмикається знову, і ряд може досунутись ще на кілька пікселів до точки прив'язки).

Деталі: лише ліва кнопка миші (`e.button !== 0` — вихід), `e.preventDefault()` на `pointerdown`; `pointercancel` завершує перетягування так само, як `pointerup`; фото не перетягуються як картинки (`.strip .ph img { -webkit-user-drag: none; pointer-events: none }`); курсор `grab` / `grabbing`. Картки шукаються як `.mq-t:not([aria-hidden]) > *`, зсув рахується з урахуванням `scroll-padding-left` контейнера.

Пальцем працює рідна прокрутка браузера, JS не втручається.

## 12. Квитки

### 12.1. Квиток нахиляється за мишею (тип C, лише з мишею)

Батько `.ticket-w { perspective: 1400px }`. Квиток — `[data-tilt]`.

Якщо остання подія вказівника була від миші (`m.mouse`) і миша в межах квитка або не далі 40 px від нього:

```
fx = clamp( (m.x − rect.left) / rect.width, 0, 1 )
fy = clamp( (m.y − rect.top) / rect.height, 0, 1 )
transform = rotateX( (0.5 − fy) × 12 deg ) rotateY( (fx − 0.5) × 14 deg )
```

Миша пішла → `transform` прибирається. Перехід `transform .18s ease-out` (згладжує рух і повернення).

Умова `m.mouse` обов'язкова: без неї квиток нахилявся б і без миші — під умовною початковою точкою вказівника посеред екрана і на телефоні після дотику. Палець чи перо квиток не нахиляють; до першого руху миші він лежить рівно.


### 12.2. Наведення на квиток

| | Десктоп | До 820 px |
|---|---|---|
| квиток, спокій | `rotate: -2deg` | `rotate: -1.5deg` |
| квиток, hover | `rotate: 0deg`, `.4s back-m` | те саме |
| корінець `.t-stub`, hover | `translate: 16px 0; rotate: 4.5deg` — відривається вбік | `translate: 0 12px; rotate: 2.5deg` — відривається вниз |
| перехід корінця | `translate/rotate .38s cubic-bezier(.3,1.7,.5,1)` | те саме |

На телефоні корінець під основною частиною, тому `transform-origin: 0 0`.

### 12.3. Єнот

Біжить по скошеному нижньому краю секції квитків. Контейнер `.coon-track`: `position: absolute; left: 0; right: 0; bottom: 0; height: 3.4vw` (висота скосу).

```css
.coon { animation: coon-run 19.48s linear infinite; rotate: 1.947deg; transform-origin: 50% 100% }
@keyframes coon-run {
  0%           { left: -30%; bottom: 130%; scale:  1 1 }   /* за лівим краєм, вище */
  19.2%        { left: 130%; bottom: -30%; scale:  1 1 }   /* добіг за правий край */
  19.21%, 50%  { left: 130%; bottom: -30%; scale: -1 1 }   /* розвернувся і чекає */
  69.2%        { left: -30%; bottom: 130%; scale: -1 1 }   /* добіг назад */
  69.21%, 100% { left: -30%; bottom: 130%; scale:  1 1 }   /* розвернувся і чекає */
}
```

- Пробіг в один бік: 19.2% × 19.48 с ≈ **3.74 с**.
- Пауза за краєм екрана: 30.8% × 19.48 с ≈ **6.0 с**, з обох боків.
- Зі зменшеним рухом єнот не бігає, а стоїть: `left: 78%; bottom: 22%` (1.4).
- Це тривалості відрізків анімації. На екрані єнота видно менше, бо частину пробігу він ще за краєм: при 1280 px — близько 2.8 с видно і 7 с не видно; при 390 px — 3.2 с і 6.5 с.
- `left` і `bottom` у відсотках від `.coon-track` — єнот іде рівно по скосу за будь-якої ширини. `rotate: 1.947deg` = кут скосу (`atan(3.4 / 100)`).

Частини тіла (`--lt` — тривалість кроку):

| Частина | Анімація | Тривалість |
|---|---|---|
| лапи `.coon-l` (4) | `coon-leg`: 0% `skewX(38deg)` → 50% `skewX(-38deg)` → 75% `skewX(0deg) scaleY(.66)` → 100% `skewX(38deg)`; точки обертання лап і хвоста вписані в розмітку (`transform-origin`) | `--lt`, `linear infinite` |
| лапи `.coon-l2` (2 з 4) | та сама, `animation-delay: calc(var(--lt) / -2)` — у протифазі | |
| тіло `.coon-b` | `coon-bob`: `translateY(0)` ↔ `translateY(-4px)` | `--lt / 2`, `ease-in-out infinite alternate` |
| хвіст `.coon-tg` | `coon-tail`: `rotate(-4deg)` ↔ `rotate(6deg)` | `--lt × 2`, `ease-in-out infinite alternate` |

`--lt`: `.15s` на десктопі, `.19s` до 820 px, `.27s` до 520 px (єнот менший — кроки рідші, інакше ноги мерехтять).

Розмір: `--ch: clamp(72px, 9.4vw, 150px)`, пропорції 2:1.

Як перевірено, що нічого видимого не зникло: повна сторінка і почищена порівняні на 9 розмірах вікна в 139 положеннях скролу — у всіх 662 елементів, що лишились, однакові розміри, позиції, класи, вписані й обчислені стилі.

Лишилось навмисно: `.ph::before` — візерунок хутра для рамки фото, в якій фото ще немає. У всіх рамок фото є (клас `has`, правило `.ph.has::before { display: none }`), тому візерунка не видно і файл `assets/patterns/fur.png` браузер не завантажує. Це не залишок старого варіанта, а запасний вигляд: якщо з'явиться рамка без фото — візерунок покажеться сам.

Що не чистилось: шари стилів. Раніше правило, перекрите пізнішим, лишається на місці — наприклад, `.hero { --bo: calc(36px + 1.9vw) }` перекрите пізнішим `.hero { --bo: 0px }`, так само кілька значень полів у `.about`, `.place`, `.pov-eye`, `.pov-act`. На вигляд це не впливає; зводити їх варто при перенесенні, перевіряючи, що підсумок не змінився (`SPEC.md`, розділ 0). У скрипті лишився об'єкт `self`, у який складаються таймери, спостерігачі й обробники: на полотні за ним знімались слухачі, на сайті його ніхто не читає.

## 16. Рішення, які вже прийняті — не змінювати

Кожне з цих рішень було зроблено інакше, показано власнику і перероблено. Не «покращувати»:

1. **Єнот біжить сам по колу з паузами (близько 7 с його не видно).** Запуск від скролу пробували — відхилено.
2. **Стрічки фото і відгуків не зупиняються при наведенні.**
3. **Абзаци теми прив'язані до скролу**, як маніфест: вгору — програється задом наперед. Варіант «від часу, один раз» і варіант «сховати і показати знову» відхилено.
4. **Цифри — пружина з відскоком**, грає щоразу при поверненні, не скидається, поки цифра хоч трохи на екрані.
5. **На лініях-контурах жодних градієнтів і згасань**, жодних прямих обрізів: контури або цілі, або їх немає.
6. **Зміна точки зору миттєва**, без плавного переходу кольору — в усіх секціях, зокрема в рядках зон (3.4).
7. **На телефоні галерея і відгуки — свайп по одній картці**, без автопрокрутки.
8. **На телефоні пояснення теми розгортається під абзацом зі словом «тему»**, а не над ним.
9. **Меню закривається миттєво**; анімована лише поява.
